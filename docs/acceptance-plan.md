# 開發與驗收對照

狀態：所有項目目前均為待實作／待驗證。本文件列出需要產生的證據，不代表任何測試或效能目標已通過。

## 1. 里程碑與測試入口

- MVP：完成原計畫的端到端流程、角色權限、資料庫保護、重試／取消／逾時與基本交易整合測試。
- 完整交付：補齊 `goal.md` 的全部性能與故障驗證，包含 100K/60 秒匯入、50 萬訂單／512MB 匯出、3,000 購票者及 2,000 WebSocket。
- 整合與並行測試使用 PostgreSQL 16；不可以 SQLite 的結果代替正式資料庫語意。
- 目標單一入口 `./scripts/run_tests.sh`，由腳本準備測試隔離、執行適用測試並輸出明確 exit code；完整壓測另由對應腳本啟動。
- 每個功能階段完成就執行適用檢查並 commit，效能與破壞性測試的實測證據在完整驗收階段補齊。

## 2. 需求與驗證案例

| ID | 範圍 | 驗證內容與必要證據 |
| --- | --- | --- |
| A01 | 一鍵啟動 | 全新 volume 以 docker compose up -d --build 啟動七個服務；migration、healthcheck、三種測試帳號與重複 seed 成功；重啟保留資料 |
| A02 | 認證與授權 | 註冊不能指定權限；以角色×資源擁有者×端點參數化測試覆蓋權限矩陣；登出、停用、改角色後舊憑證在下一次驗證失敗；量測 DB 查驗成本 |
| A03 | 活動生命週期 | 草稿匯入與發布；兩個編輯只有一個版本成功；發布後固定配置／價格／售票時段；有訂單即禁止刪除；匯入受理與發布競爭不造成發布後繼續新增座位；刪除／購票並行只能一邊成功，不產生已刪除活動的新訂單 |
| A04 | 固定分頁 | 開始查詢後持續新增、修改排序／篩選欄位與刪除資料；原快照中的結果恰好出現一次且投影不變；10 分鐘過期、撤銷 session、auth_version 變更皆正確處理 |
| A05 | 匯入格式與限制 | CSV／JSON、20,000,000 bytes 與 100,000 列的邊界；未知區域、缺欄、錯誤型別、檔案內與既有座位重複；報告含原始位置及原因 |
| A06 | 匯入原子性與恢復 | all_or_nothing 有錯零新增；skip_invalid 只新增有效列；在批次提交前後中止並重啟，checkpoint 不遺失、不重複；同檔案並行受理只產生一個 job；換模式仍回原 job；舊 generation 不能提交 |
| A07 | 同座位競爭 | 多帳號同時指定同座位，最多一筆有效保留與一筆成交；同一請求含重複 ID 不成功；過期座位接手後，舊取消／逾時工作不釋放新保留 |
| A08 | 跨訂單限購 | 同帳號以不同 key 並行送 3+2、4+4 張，成功後有效保留與已付張數合計不超過 4；過期但尚未清理的訂單不占有效額度；Admin 購票同樣受限 |
| A09 | 區域配位 | 多筆配位不重複，足額或失敗；資料庫內挑選，無應用程式先讀後寫競爭；暫時鎖衝突與真正不足的回應可辨識；測試不同交易的鎖定順序 |
| A10 | API 冪等 | 已完成、處理中、不同內容三種情境；DB 提交後故意丟失回應，重試仍得同訂單；程序中止後接手租約，舊 generation 不重複提交 |
| A11 | 金流 | 成功、失敗後重試、重複／偽造／金額不符回呼、逾時後成功、取消後成功；既有訂單不得復活；provider 已沖正但 backend 未確認時重試無額外副作用 |
| A12 | 截止時間 | 用資料庫種入過去／未來期限與同步 barrier，測試取得鎖後重新判斷；模擬應用程式時鐘偏差；避免靠 sleep 等真實 5 分鐘才驗證 |
| A13 | 重複背景工作 | 兩個 worker 同時執行逾時／Outbox／查帳／沖正／匯入批次；終態與實際座位／金額一致；lease fencing 與條件式狀態轉移有效 |
| A14 | 即時一致性 | snapshot／訂閱交界、重複／亂序／跳號事件、最後一筆事件漏失且後續無新事件；每 5 秒版本核對可發現缺口；緩衝滿斷線後重新同步 |
| A15 | 部分失敗 | 在 DB commit 後 publish 前、publish 後 ack 前、provider 成功後 callback 前、沖正後確認前強制中止；記錄恢復流程、實際時間與是否需人工處理 |
| A16 | 指標與診斷持久化 | 兩個 API 副本、不同 instance ID、OS 時鐘慢 20 秒、collector 重送；PG 提交後才 XACK；Redis 不可用的 spool 後備與回放；資料缺漏不可當成正常零值 |
| A17 | 監控與告警 | 已知延遲樣本的跨副本百分位數、RPS、例外／5xx 去重、業務拒絕分類、連線 gauge；三種門檻、至少 20 請求與持續 15 秒規則；解除後保留歷史 |
| A18 | 報表 | Summary／Zones／Orders 三工作表，同一一致快照；Asia/Taipei 表頭、數值金額、服務費半元邊界、狀態與銷售額正確；報表的 Viewer／User／Admin 權限 |
| A19 | request_id | 一次購票／付款／匯入橫跨 API、worker、gateway 與 callback 後，可由 Admin 查到關聯日誌；一般使用者不得讀取；日誌無憑證或秘密 |
| A20 | 操作介面 | 三角色端到端：登入→建立活動→匯入→發布→選位→鎖位→付款→即時更新→監控→Excel；取消、重試、錯誤、失同步與權限不足具有可理解回饋 |
| A21 | 效能完整驗收 | 下表的四種指定情境實際執行；保留機器規格、版本、測試配置、原始輸出、RPS、p50/p95/p99、錯誤分類、峰值 RSS 與結束後一致性檢查 |
| A22 | 交付文件與歷史 | GitHub 私有目標、階段 commit、不 squash；README、DESIGN、LOADTEST、AI_USAGE、env 說明、範例與架構圖完整，未完成項目明確列出 |

以上是有實際業務風險的驗證案例；不另寫只重述資料夾或常數內容的測試。

| 情境 | 固定條件 | 記錄方式 |
| --- | --- | --- |

| 搶票 A | 單活動 10,000 座位、3,000 虛擬使用者持續 60 秒 | 註明登入帳號分配、每帳號 4 張限制、等待時間、指定／配位比例與預期售罄；業務衝突和系統錯誤分列 |
| 即時 B | 2,000 連線訂閱同一活動 | 另外產生座位變更；記錄連線數、傳播延遲、慢連線斷線、重新同步成功率與實際記憶體 |

若硬體或工作階段限制使情境無法執行，記錄「未執行」與實際原因，不縮小情境後宣稱完整要求通過。可另外保留小規模開發驗證，但不可取代指定情境。

## 4. DESIGN.md 證據對應

| goal.md 設計題 | 實作後必須填入 |
| --- | --- |
| Q1 不超賣 | 真實檔案／行號、取得與釋放保護點、故障時間線、並行測試與故意改壞後的實際失敗輸出 |
| Q2 部分失敗 | 至少三個時間窗、最危險案例、kill -9 恢復耗時、DB 時鐘與無 sleep 測試、兩 worker 的保護行號 |
| Q3 冪等與限購 | 三種重試 HTTP 結果、額度與寫入的交易位置、資料庫配位的並行測試 |
| Q4 推送 | commit→Outbox→Redis→各副本→瀏覽器路徑、邏輯順序與故障到達順序區別、漏失偵測與慢客戶端代價、B 實測 |
| Q5 授權 | 撤銷語意及在途操作邊界、每次認證成本實測、已受理匯入決策、參數化權限矩陣與容易漏掉的端點 |
| Q6 監控 | 每指標的來源／窗口／儲存、業務失敗但 HTTP 正常的辨識、時鐘偏差、去重／回放與權威來源；揭露數據缺漏 |

故意改壞保護只在隔離的臨時測試資料庫與程式副本進行，取得預期失敗後還原並重新通過正式測試。正式 migration 與交付程式保留保護，不以刪除限制換取綠燈。

## 5. 證據與已知限制

- LOADTEST 的數字只取自原始輸出，保留執行時間、commit SHA、環境與配置。單純 kill 程序不能當成已驗證主機斷電與儲存故障的持久性。
- AI_USAGE 收集真正發現的 AI 程式錯誤、發現方法、修正與驗證；缺少三個真實案例時如實標示，不能編造或把刻意破壞的變體充當自然發生的錯誤。
- 目前工作階段曾因 Docker socket 權限無法執行 Compose，GitHub 查詢亦曾因網路失敗；後續會再驗證可用通道。此階段沒有應用程式、資料庫、容器或效能測試的成功證據。
